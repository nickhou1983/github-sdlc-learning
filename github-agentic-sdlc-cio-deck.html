底座如何关联？ · GRAPH & INDEX
原生对象图谱 + 代码语义索引
Timeline 双向引用图谱：在 GitHub 底层 GraphQL 数据库中，父 Issue #1 ↔ Sub-issue #2 ↔ 分支 ↔ Commit ↔ PR (`Fixes #2`) ↔ Actions 日志 ↔ CodeQL 告警 形成天然连通图
Blackbird + AST 符号 + 向量索引：代码推送时后台自动构建极速倒排索引、Tree-sitter 跨文件符号调用树与向量化语义索引
Copilot Spaces & Memory：Spaces 将跨仓库微服务契约与文档聚合成领域知识包；Memory 跨会话保留仓库构建命令与排障记忆

四级指令按路径精准触发：启动必载 copilot-instructions.md 与 AGENTS.md；当读写 src/inventory/** 时，自动匹配 applyTo 动态注入乐观锁规范
告别手工搬运背景：无论在 IDE、Copilot App 还是云端沙箱启动，第一秒即自动对齐架构红线

运行如何检索？ · MCP & TOOLS
渐进式按需检索与窗口治理

从代码反查历史决策：内置 GitHub MCP 工具（pull_request_read / issue_read / git blame）可随时穿透查询“半年前哪个 PR 为什么这么改”
Context Compaction & RBAC：长任务自动将中间探索输出压缩为 Checkpoint 摘要防遗忘；全程受触发者 OAuth/App 令牌权限约束
架构本质：GitHub 将“静态代码库 + 动态协作历史 + 团队工程规范 + 运行时工具检索”融合为统一的上下文操作系统。

附录 B：能力 2.2 中“异步 Agent 团队”是如何协同运转的？

开发者从单线程问答者升级为 Tech Lead（技术负责人），通过“角色专业化 ➔ Sub-issues 拆单 ➔ 隔离工位并发 ➔ Agent HQ 集中管控”指挥虚拟工程小队。
AGENT TEAM ORCHESTRATION // 1 名人类架构师如何通过三端入口与 Agent HQ 指挥多工种 Agent 并发 1 TECH LEAD × N SPECIALIST AGENTS
MECH 01 · ROLES & AGENTS
成员角色专业化
内置 Ask / Plan / Agent + 仓库 .github/agents/*.agent.md 专家
➔
MECH 02 · SUB-ISSUES
工单化层级拆单派活
父 Issue 经 Plan 对齐后拆为多个 Sub-issues 指派不同 Agent
➔
MECH 03 · ISOLATED TARGETS
三类隔离工位并发
IDE 前台 + 本地 Git Worktree 后台 + Actions 云端沙箱互不覆写
➔
MECH 04 · AGENT HQ
集中监控与中途纠偏
统一查看进度、回答阻塞提问（ask_user）、审批 Plan 与自审 PR
机制一 · 成员专业化（Built-in Roles + Custom Agents） .github/agents/*.agent.md
内置三角色分工 + 团队自定义领域专家与 Subagents 派生

内置角色：Ask（答疑）、Plan（只读跨服务诊断并输出 Markdown 实施计划，不改代码）、Agent（自主改码并可动态派生临时 Subagents 子智能体并发搜索或跑测试）。
自定义专家：在 .github/agents/ 下定义业务专家（@inventory-impl）、混沌测试专家（@chaos-qa）、SRE 专家（@sre-observability），各自绑定专属 Prompt 与 MCP 工具权限。

机制二 · 工单化派活（GitHub Issues + Sub-issues） HIERARCHICAL DISPATCH
像管理真人研发团队一样拆分父子工单并按角色指派

父子层级拆解：复杂需求在父 Issue（如 #1）经人类架构师确认 Plan 后，原生拆解为多个 Sub-issues（#2 业务、#3 压测、#4 运维）。
一键指派与进度汇聚：在 GitHub Issues 看板或 Copilot App 中将不同子单的 Assignees 指派给对应 Agent，各子单 PR 状态与验收进度自动汇总回父 Issue。

机制三 · 工位物理隔离（Three Session Targets） LOCAL · WORKTREE · CLOUD
每个 Agent 拥有独立文件系统与运行沙箱，多路并发零冲突

1. Local Agent（前台工位）：在当前 IDE 中与开发者实时结对攻克核心算法；
2. Background Agent（本地后台工位）：通过 Copilot App / CLI 自动创建隔离的 本地 Git Worktree 分支目录后台并发跑测试；
3. Cloud Agent（云端工位）：在 GitHub Actions 隔离容器中独立克隆、编码、跑 CI、完成 Copilot Code Review 自审后交付就绪 PR。

机制四 · 集中式管理台（Agent HQ + 三端入口接力） MISSION CONTROL & STEERING
告别在十几个终端窗口间盯守，统一审批、应答与中途纠偏

全状态可观测：在 Agent HQ / Copilot App 集中查看所有会话是“运行中”、“等待审批 Plan（pending_plan）”还是“遇到歧义请求人工拍板（awaiting_input）”。
实时插话与跨端移交：支持向正在运行的 Agent 发送指令实时调整方向（Steer），或通过 /delegate 将本地未完会话一键移交至云端继续执行。

组织效能跃迁：1 名资深工程师借助“专业角色 + Worktree/Cloud 隔离沙箱 + Agent HQ”，即可具备一整支全栈特性小组的并行吞吐力。
